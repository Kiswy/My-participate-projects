多功能预约系统后端开发思路总结（SQL Server 版）

一、当前项目情况

你现在有两个项目：

1. Web 项目

路径：
E:\Projects\java\codes\appointmentSystem

当前技术：
JSP + Tomcat + Vue

目前情况：
前端页面基本已经完成，包含登录、注册、预约大厅、我的预约、预约概览、项目管理等页面。
但是业务数据目前是写死在页面里的，例如 homepage_Max.jsp 里的 serviceCategories、reservationCards、appointmentForm、projectManagement。

后端目前还没有真正开始实现。
src\Main.java 只是默认 Java 模板，不是实际后端业务代码。

2. Android 项目

路径：
E:\Projects\java\codes\appointmentSystemAndroid

当前技术：
原生 Android Java

目前情况：
Android 已经有登录、注册、预约大厅、我的预约等页面。
但是 BookingHallFragment 和 MyReservationFragment 里目前使用的是 loadMockData() 假数据。

所以后端的目标应该是：

同一个 Java 后端
同时给 Web 前端提供接口
同时给 Android App 提供接口

不要给 Web 和 Android 分别做两套后端。


二、后端总体思路

你的系统应该拆成三部分理解：

1. 前端

负责显示页面、按钮、输入框、列表。

Web 前端：
JSP + Vue

Android 前端：
Activity + Fragment + RecyclerView

2. 后端

负责处理业务逻辑，例如：

取消预约
查看我的预约
后台新增项目
后台删除项目
后台查看全部预约记录

3. 数据库

负责长期保存数据，例如：

用户账号
预约分类
预约项目
预约记录
预约状态

你希望数据库使用 SQL Server，因此后端数据存储方案建议使用：

SQL Server

更推荐的方案是 token。

  "data": {

    "user": {
      "id": 1,
      "username": "lihua",
      "role": "USER"
    }
  }
}

之后 Web 和 Android 每次请求都带上 token。


四、推荐后端技术路线

因为你的 Web 项目现在是 JSP + Tomcat，建议第一阶段不要直接上复杂框架。

第一阶段推荐：

Servlet + JDBC + SQL Server + JSON

优点：

适合零基础理解后端原理
能直接接上你现在的 JSP/Tomcat 项目
代码结构比较直观
方便同时给 Android 提供接口

第二阶段可以升级：

Spring Boot + MyBatis 或 MyBatis-Plus + SQL Server

优点：

开发效率更高
接口写法更规范
更接近真实企业项目

但是不建议一开始就直接 Spring Boot。
先把 Servlet + JDBC 跑通，对后端理解会更扎实。


五、数据库设计（SQL Server）

数据库建议命名：

AppointmentSystem

核心数据表建议有四张：

1. users 用户表

作用：
保存登录注册用户。

字段建议：

id
用户 ID，主键，自增。

username
用户名，不能重复。

password_hash
密码。注意正式项目不要直接明文保存密码。

real_name
真实姓名。

email
邮箱。

phone
手机号。

role
角色。普通用户为 USER，管理员为 ADMIN。

created_at
创建时间。

SQL Server 建表示例：

CREATE TABLE users (
    id INT IDENTITY(1,1) PRIMARY KEY,
    username NVARCHAR(50) NOT NULL UNIQUE,
    password_hash NVARCHAR(255) NOT NULL,
    real_name NVARCHAR(50),
    email NVARCHAR(100),
    phone NVARCHAR(30),
    role NVARCHAR(20) NOT NULL DEFAULT 'USER',
    created_at DATETIME2 NOT NULL DEFAULT SYSDATETIME()
);

2. categories 预约分类表

作用：
保存预约项目分类。

例如：
图书馆
讲座
活动室
体育场馆

字段建议：

id
分类 ID，主键，自增。

name
分类名称。

SQL Server 建表示例：

CREATE TABLE categories (
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(50) NOT NULL UNIQUE
);

3. projects 预约项目表

作用：
保存可以被预约的项目。

例如：
图书馆·自习室
图书馆·研讨室
AI 前沿讲座
心理健康公开课

字段建议：

id
项目 ID，主键，自增。

category_id
分类 ID，关联 categories 表。

title
项目名称。

description
项目说明。

location
地点。

start_time
开始时间。

end_time
结束时间。

capacity
总容量。

status
状态。OPEN 表示开放预约，CLOSED 表示关闭预约。

created_at
创建时间。

SQL Server 建表示例：

CREATE TABLE projects (
    id INT IDENTITY(1,1) PRIMARY KEY,
    category_id INT NOT NULL,
    title NVARCHAR(100) NOT NULL,
    description NVARCHAR(500),
    location NVARCHAR(100),
    start_time DATETIME2 NOT NULL,
    end_time DATETIME2 NOT NULL,
    capacity INT NOT NULL,
    status NVARCHAR(20) NOT NULL DEFAULT 'OPEN',
    created_at DATETIME2 NOT NULL DEFAULT SYSDATETIME(),
    CONSTRAINT fk_projects_category
        FOREIGN KEY (category_id) REFERENCES categories(id)
);

4. reservations 预约记录表

作用：
保存用户的预约记录。

字段建议：

id
预约 ID，主键，自增。

user_id
用户 ID，关联 users 表。

project_id
项目 ID，关联 projects 表。

reservation_code
预约码。

status
预约状态。BOOKED 表示已预约，CANCELLED 表示已取消。

created_at
预约时间。

cancelled_at
取消时间。

SQL Server 建表示例：

CREATE TABLE reservations (
    id INT IDENTITY(1,1) PRIMARY KEY,
    user_id INT NOT NULL,
    project_id INT NOT NULL,
    reservation_code NVARCHAR(50) NOT NULL UNIQUE,
    status NVARCHAR(20) NOT NULL DEFAULT 'BOOKED',
    created_at DATETIME2 NOT NULL DEFAULT SYSDATETIME(),
    cancelled_at DATETIME2 NULL,
    CONSTRAINT fk_reservations_user
        FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT fk_reservations_project
        FOREIGN KEY (project_id) REFERENCES projects(id)
);

为了防止同一个用户重复预约同一个项目，建议额外加唯一约束。
但是因为 SQL Server 对带条件的唯一约束处理稍复杂，入门阶段可以先在 Java 代码里判断：

同一个 user_id + project_id，且 status = 'BOOKED' 时，不允许重复预约。


六、为什么不建议把 remaining 直接存在 projects 表里

前端页面里有 remaining 和 capacity。

capacity 是总容量，适合存数据库。

remaining 是剩余名额，可以通过计算得到：

remaining = capacity - 已预约人数

已预约人数来自 reservations 表：

SELECT COUNT(*)
FROM reservations
WHERE project_id = ?
  AND status = 'BOOKED';

这样更准确。

如果你直接把 remaining 存在 projects 表里，也可以做，但需要每次预约成功就减 1，取消预约就加 1。
对于初学者来说，容易出现数据不一致。

所以建议：

projects 表存 capacity。
reservations 表存预约记录。
查询时计算 remaining。

八、Web 和 Android 如何共用接口

不要让 Android 访问 JSP 页面。

错误方式：

Android 访问 /index.jsp
Android 访问 /homepage.jsp

正确方式：

Android 访问 /api/auth/login
Android 访问 /api/projects
Android 访问 /api/reservations/my

Web 页面也访问同一套接口：

JSP/Vue 访问 /api/projects
JSP/Vue 访问 /api/reservations/my
JSP/Vue 访问 /api/admin/reservations

这样后端只需要写一套。

4. Android 调试地址

如果使用 Android 模拟器访问电脑上的 Tomcat：

http://10.0.2.2:8080/项目名/api/projects

不能写：

http://localhost:8080

因为 Android 模拟器里的 localhost 指的是模拟器自己，不是你的电脑。

如果使用真机访问电脑上的 Tomcat，需要写电脑的局域网 IP：

http://192.168.x.x:8080/项目名/api/projects

电脑和手机必须在同一个局域网。


十、SQL Server JDBC 连接说明

Java 连接 SQL Server 需要 SQL Server JDBC Driver。

常见连接字符串：

jdbc:sqlserver://localhost:1433;databaseName=AppointmentSystem;encrypt=false;trustServerCertificate=true

需要的信息：

数据库地址：
localhost

端口：
1433

数据库名：
AppointmentSystem

用户名：
例如 sa

密码：
你安装 SQL Server 时设置的密码

JDBC 查询流程大概是：

1. 获取数据库连接
2. 写 SQL
3. 使用 PreparedStatement 设置参数
4. 执行 SQL
5. 如果是查询，读取 ResultSet
6. 把结果转换成 Java 对象
7. 返回 JSON 给前端或 Android

十二、核心业务逻辑说明

1. 注册

前端输入用户名和密码。
后端检查用户名是否存在。
如果不存在，插入 users 表。

2. 登录

前端输入用户名和密码。
后端查询 users 表。
判断密码是否正确。
正确则返回用户信息和 token。

3. 查询预约大厅

后端查询 projects 表。
关联 categories 表。
再统计 reservations 表里的已预约人数。
计算 remaining。
返回给 Web 和 Android。

4. 立即预约

后端检查用户是否登录。
检查项目是否存在。
检查项目是否开放。
检查是否还有剩余名额。
检查用户是否重复预约。
生成预约码。
插入 reservations 表。

5. 我的预约

后端根据当前用户 ID 查询 reservations。
关联 projects。
返回项目名称、预约码、预约人、日期、状态。

6. 取消预约

后端不建议直接删除预约记录。
建议把状态改成 CANCELLED。
这样后台还能看到历史数据。

7. 后台项目管理

管理员可以新增项目、修改项目、关闭项目。
如果项目已经有人预约，不建议直接删除。


十三、推荐开发顺序

建议按下面顺序开发：

1. 安装并配置 SQL Server
2. 使用 SSMS 创建 AppointmentSystem 数据库
3. 创建 users、categories、projects、reservations 表
4. 插入几条测试分类和项目数据
5. 在 Java Web 项目中加入 SQL Server JDBC 驱动
6. 写 DbUtil 数据库连接工具类
7. 写 User、Project、Reservation、Category 实体类
8. 写 UserDao，先完成注册和登录需要的 SQL
9. 写注册 Servlet
10. 写登录 Servlet
11. 写 ProjectDao

十四、给零基础的理解总结

你可以把整个系统理解成：

数据库：
负责存数据。

后端：
负责判断规则和操作数据库。

Web 前端：
负责显示网页。

Android：
负责显示手机 App 页面。

接口：
是 Web、Android 和后端之间沟通的通道。

你的后端最重要的任务不是做页面，而是提供 JSON 接口。

最终目标：

用户在 Web 上预约一个项目，数据库会新增一条预约记录。
用户再打开 Android，也能看到同一条预约。

用户在 Android 上取消预约，数据库会更新状态。
管理员在 Web 后台，也能看到这条预约已经取消。

这就是 Web 和 Android 共用同一个后端、同一个 SQL Server 数据库的意义。


十五、最终推荐方案

数据库：
SQL Server

第一阶段后端：
Servlet + JDBC + SQL Server + JSON

Web 前端：
JSP + Vue 调用 /api 接口

Android：
原生 Java + OkHttp 调用同一套 /api 接口

后期升级：
Spring Boot + MyBatis/MyBatis-Plus + SQL Server

最核心的一句话：

SQL Server 保存真实数据，Java 后端负责业务逻辑，Web 和 Android 都只负责调用接口和显示结果。
